# 프론트엔드 실행 가이드 (UI 작업 1~4번)

백엔드 API 연동은 차후 진행하고, **self-web에서 UI 및 화면 기능만 우선 작업**할 때의 실행·테스트 방법을 정리한 문서입니다.

---

## 아키텍처 요약

```
APK (self-android)          self-web (Nuxt)           self-server (Spring)
WebView 껍데기        →     사용자 화면          →     API (차후 연동)
```

- APK 자체에는 UI 코드가 없습니다. WebView가 웹 페이지를 불러옵니다.
- 화면 수정은 `self-web\self-web`에서 합니다.
- 작업 브랜치: **`develop`** (사용자 앱)

| 저장소 | 경로 | 역할 |
|--------|------|------|
| self-web | `C:\projects\self\self-web\self-web` | 사용자 화면 (Nuxt) |
| self-android | `C:\projects\self\self-android` | WebView APK |
| 운영 서버 | `http://210.120.6.98:7080` | 화면 + API 통합 서비스 |

---

## 작업 범위 (프론트만)

| 할 것 | 안 해도 되는 것 |
|--------|----------------|
| `self-web` 화면·폼·유효성 검사 | `self-server` API 구현 |
| 로컬 상태로 입력값 관리 | 실제 저장/조회 연동 |
| 브라우저 또는 APK에서 화면 확인 | 서버 배포 |
| 목업 → Vue 페이지 코드 반영 | `axios` baseURL 변경 (당분간) |

API는 나중에 붙일 때 `composables/api/*`와 각 페이지의 submit 로직만 연결하면 됩니다.

## 핵심 개념: PC npm 실행 → 폰에서 보이는 원리

**폰 APK 안에 화면 코드가 들어있는 게 아닙니다.**

폰에 설치되는 APK는 **크롬 같은 미니 브라우저(WebView)** 하나뿐이고,  
그 브라우저가 **PC에서 돌아가는 웹 서버 주소**를 열어서 화면을 보여줍니다.

```
┌──────────────────── PC ────────────────────┐
│  signup.vue 등 소스 코드                    │
│       ↓ 저장                                │
│  npm run dev  →  웹 서버가 :3000 포트에서 대기 │
│       ↓ HTTP 요청이 오면 HTML/JS/CSS 응답    │
└──────────────────┬─────────────────────────┘
                   │  USB 또는 Wi-Fi로 통신
┌──────────────────▼─────────────────────────┐
│  폰 (APK)                                  │
│  MainActivity → WebView                    │
│  "http://127.0.0.1:3000/splash" 접속 요청   │
│       ↓                                    │
│  PC 웹 서버가 보낸 페이지를 폰 화면에 표시    │
└────────────────────────────────────────────┘
```

| 비유 | 설명 |
|------|------|
| PC `npm run dev` | PC에서 잠시 웹사이트를 열어 두는 것 (포트 3000) |
| APK | 그 웹사이트 주소를 즐겨찾기로 열어두는 전용 브라우저 앱 |
| 코드 수정 | PC 웹사이트 내용이 바뀜 → 폰에서 앱 다시 열면 변경 반영 |

**운영 APK**는 `http://210.120.6.98:7080`(서버)을 엽니다.  
**개발 테스트**는 `http://127.0.0.1:3000`(내 PC)을 열도록 APK 설정을 잠시 바꿉니다.

## 1~4번 작업 순서 (상세)

### 1번 — PC에 self-web 설치·실행

#### 1-1. npm install (최초 1회)

```powershell
cd C:\projects\self\self-web\self-web
npm install
```

- `package.json`에 적힌 라이브러리(Nuxt, Vue 등)를 PC에 다운로드합니다.
- `node_modules` 폴더가 생깁니다.
- **폰과는 무관합니다.** PC에서만 필요합니다.

#### 1-2. npm run dev (작업할 때마다 켜 둠)

```powershell
npm run dev
```

터미널에 아래처럼 나오면 성공입니다.

```
  ➜ Local:   http://localhost:3000/
```

이 순간 PC 안에서 **웹 서버**가 켜집니다.

| 상태 | 의미 |
|------|------|
| 터미널 창이 열려 있음 | 서버가 살아 있음 → 폰 APK가 접속 가능 |
| 터미널을 닫거나 Ctrl+C | 서버 종료 → 폰 APK는 빈 화면·연결 오류 |

#### 1-3. PC 브라우저로 먼저 확인 (선택)

PC 크롬에서 `http://localhost:3000/signup` 접속 → 화면이 보이면 1번 완료.

> **이 단계까지는 폰 필요 없습니다.**

---

### 2번 — 목업 기준 Vue 페이지 수정

PC에서 `signup.vue` 등 파일을 수정하고 저장합니다.

| 목업 | 수정 파일 | 참고 |
|------|-----------|------|
| 회원가입 백신 접종 | `pages/signup.vue` (Step 2) | `components/modal/diagnosis.vue` (백신 UI 패턴) |
| 증상시작 / 14일이내 / 근무지 / 동거인 안내 | 해당 페이지 | `수정사항/` 폴더 목업 PNG·HTML |

- 저장하면 `npm run dev`가 자동으로 변경을 반영합니다 (HMR).
- PC 브라우저를 새로고침하면 바로 확인 가능.
- **아직 폰에는 반영 안 됨** — 4번에서 APK로 접속해야 폰에 보입니다.

---

### 3번 — 프론트만 동작하게 구현

백엔드 API 없이 화면만 동작하게 만듭니다.

- yes/no 선택 → 접종일 필드 show/hide
- 날짜 8자리 유효성 검사
- `forms` 객체에 필드 추가

```typescript
// 지금: UI만 — submit 시 console.log 또는 mock 처리
// 나중: mainApi.xxx() 호출로 교체
```

회원가입은 Step 1·완료 시 API를 호출하므로, UI만 볼 때는 Step 2로 바로 진입하거나 API 검증을 잠시 우회합니다.

---

### 4번 — 폰 APK에서 확인

**1~3번은 PC에서, 4번은 폰에서 봅니다.**  
단, 4번이 동작하려면 **1번의 `npm run dev`가 PC에서 계속 켜져 있어야** 합니다.

#### 4번이 동작하는 조건 (3가지가 모두 맞아야 함)

```
① PC: npm run dev 실행 중 (:3000)
② APK: MainActivity URL이 PC 주소를 가리킴 (임시 변경)
③ 폰: debug APK 설치 + PC와 연결 (USB 또는 같은 Wi-Fi)
```

하나라도 빠지면 폰에서 화면이 안 나옵니다.

## PC → 폰 연결: 최초 1회 세팅 (USB 방식, 추천)

아래는 **처음 한 번만** 하면 됩니다. 이후에는 1번(`npm run dev`) + 폰에서 앱 열기만 반복합니다.

### Step 0. 사전 준비

| 준비물 | 설명 |
|--------|------|
| Node.js | PC에 설치 (npm 포함) |
| Android Studio 또는 JDK | APK 빌드용 |
| USB 케이블 | 폰 ↔ PC 연결 |
| 폰 개발자 옵션 | 설정 → 휴대전화 정보 → 빌드번호 7회 탭 |
| USB 디버깅 | 개발자 옵션에서 ON |

### Step 1. APK가 PC를 바라보도록 URL 변경

`self-android/app/src/main/java/com/smmit/self2/MainActivity.kt` 130번째 줄:

```kotlin
// 변경 전 (운영 서버)
val base = "http://210.120.6.98:7080"

// 변경 후 (내 PC dev 서버) — 개발 테스트용
val base = "http://127.0.0.1:3000"
```

> 이 파일을 바꾸면 **APK를 다시 빌드·설치**해야 합니다.  
> 이후 `signup.vue`만 수정할 때는 재빌드 불필요.

### Step 2. debug APK 빌드

```powershell
cd C:\projects\self\self-android
.\gradlew assembleDebug
```

완료되면 APK 생성:

```
app\build\outputs\apk\debug\app-debug.apk
```

### Step 3. 폰에 APK 설치

```powershell
# 폰 USB 연결 후
adb devices          # 폰이 목록에 보이는지 확인

adb install app\build\outputs\apk\debug\app-debug.apk
```

폰 홈 화면에 **스마트 자가진단** 앱이 생깁니다.

### Step 4. PC에서 dev 서버 실행

```powershell
cd C:\projects\self\self-web\self-web
npm run dev
```

터미널을 **닫지 말고** 켜 둡니다.

### Step 5. USB 터널 연결 (adb reverse)

```powershell
adb reverse tcp:3000 tcp:3000
```

**이 명령이 하는 일:**

```
폰 입장:  127.0.0.1:3000  (= 내 폰 자신의 3000번 포트)
              ↓ USB 터널
PC 입장:  localhost:3000   (= npm run dev 서버)
```

APK가 `http://127.0.0.1:3000`을 열면, 실제로는 **PC의 dev 서버**에 연결됩니다.  
Wi-Fi IP를 몰라도 되는 이유가 여기 있습니다.

> PC를 재부팅하거나 USB를 뺐다 꽂으면 `adb reverse`를 다시 실행하세요.

### Step 6. 폰에서 앱 실행

1. 폰에서 **스마트 자가진단** 앱 아이콘 탭
2. APK 내부 WebView가 `http://127.0.0.1:3000/splash` 요청
3. PC의 Nuxt 서버가 HTML/JS/CSS 응답
4. **폰 화면에 스플래시 → 권한 → 회원가입 화면 표시**

## 매일 반복하는 작업 루프

최초 세팅(Step 1~3)이 끝났다면, 이후 매일은 아래만 반복합니다.

```
1. PC: npm run dev 실행 (터미널 켜 둠)
2. PC: adb reverse tcp:3000 tcp:3000  (USB 재연결 시)
3. PC: signup.vue 등 코드 수정 → 저장
4. 폰: 앱을 닫았다가 다시 열기 (또는 해당 페이지로 이동)
5. 폰: 수정된 UI 확인
```

| 행동 | APK 재빌드 필요? |
|------|------------------|
| `signup.vue` 등 웹 코드 수정 | ❌ 불필요 |
| `MainActivity.kt` URL 변경 | ✅ 필요 |
| `npm run dev` 재시작 | ❌ 불필요 (앱만 다시 열면 됨) |

## 폰에서 실제로 일어나는 일 (앱 실행 시)

```
[폰] 앱 아이콘 탭
  ↓
[APK] MainActivity 시작
  ↓
[APK] WebView 생성
  ↓
[APK] webView.loadUrl("http://127.0.0.1:3000/splash")
  ↓
[USB 터널] 폰 127.0.0.1:3000 → PC localhost:3000
  ↓
[PC] Nuxt dev 서버가 /splash 페이지 HTML 응답
  ↓
[폰] WebView가 HTML을 렌더링 → 스플래시 화면 표시
  ↓
[폰] 권한 확인 후 / 또는 /intro 또는 /signup 이동
  ↓
[폰] 회원가입 등 작업 화면 표시  ← 여기서 2~3번에서 만든 UI 확인
```

**폰은 화면을 "실행"하는 게 아니라 "받아서 보여주기"만 합니다.**  
실제 화면 로직은 전부 PC의 `npm run dev` 서버가 처리합니다.

## Wi-Fi 방식 (USB 없이)

USB 대신 같은 Wi-Fi를 쓸 때:

```powershell
# PC에서 외부 접속 허용
npx nuxt dev --host 0.0.0.0
```

```kotlin
val base = "http://192.168.x.x:3000"   # PC IP (ipconfig로 확인)
```

`adb reverse`는 필요 없습니다. 폰이 PC IP로 직접 접속합니다.

## 자주 막히는 지점

| 증상 | 원인 | 해결 |
|------|------|------|
| 폰에서 빈 화면 / 연결 오류 | PC `npm run dev` 꺼짐 | 터미널에서 다시 실행 |
| 폰에서 빈 화면 | `adb reverse` 안 함 | `adb reverse tcp:3000 tcp:3000` |
| 운영 화면만 보임 | APK가 서버 URL 가리킴 | `MainActivity.kt` → `127.0.0.1:3000` + 재빌드 |
| `adb devices`에 폰 없음 | USB 디버깅 OFF | 개발자 옵션에서 ON |
| 코드 수정해도 폰에 안 바뀜 | WebView 캐시 | 앱 완전 종료 후 재실행 |
| Step 1에서 다음으로 안 넘어감 | `idCheck` API 필요 | UI만 볼 때 Step 2 직접 진입 |

## 백엔드 없이 테스트할 때 (API 주의)

회원가입(`signup.vue`)은 일부 단계에서 API를 호출합니다.

| 구간 | API | 백엔드 없을 때 |
|------|-----|----------------|
| `/splash` | 없음 | ✅ 가능 |
| `/signup` Step 2 화면 | 없음 | ✅ 가능 (해당 단계 진입 시) |
| Step 1 → Step 2 | `mainApi.idCheck` | ❌ 서버 없으면 막힘 |
| Step 2 완료 | `mainApi.signup` | ❌ 완료 화면까지 안 감 |

`/signup`은 `app.vue` 예외 목록에 있어 FCM API로 막히지는 않습니다.

**UI만 볼 때 실무 팁:**

- Step 2(백신 UI)만 확인: 개발 중 Step 1 API 검증을 잠시 우회하거나, `active.order = 2`로 바로 진입
- submit은 `console.log` 또는 mock 처리

| 항목 | UI 작업 시 |
|------|------------|

| 기존 `app-release.apk` | 운영 서버 UI만 표시 (로컬 수정 반영 안 됨) |

## 주의사항

1. **`MainActivity` URL 변경은 개발용 임시 설정** — 테스트 후 `http://210.120.6.98:7080`으로 되돌려야 합니다.
2. **코드 수정 ≠ APK 재빌드** — URL을 바꾸지 않았다면 dev 서버만 켜 두고 앱을 다시 열면 됩니다.
3. **PNG/HTML 목업만으로는 APK에 반영되지 않습니다** — 반드시 `self-web` Vue 코드에 구현해야 합니다.
4. HTTP 로컬 연결은 `AndroidManifest.xml`에 `usesCleartextTraffic="true"`가 이미 설정되어 있습니다.
