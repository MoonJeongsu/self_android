# 진단 문항 삭제 영향 분석

> 작성일: 2026-07-15

## 삭제 대상

AS-IS의 세부 진단 7문항 중 다음 두 문항을 삭제한다.

1. `소화기 증상이 있나요? (복통, 설사 등)` — 기존 3번
2. `접촉 이후 증상이 시작되었나요?` — 기존 5번

현재 로컬 `self-web`의 `components/modal/diagnosis.vue`에는 두 문항이 이미 삭제되어 있다.

## 변경 전후 문항

### AS-IS: 7문항

1. 증상 시작 시점
2. 급성 호흡기 증상
3. 소화기 증상 **(삭제)**
4. 14일 이내 유증상자 접촉 여부
5. 접촉 이후 증상 시작 여부 **(삭제)**
6. 동거인 감염 여부
7. 동거인 완치 여부

### TO-BE: 5문항

1. 증상 시작 시점
2. 급성 호흡기 증상
3. 14일 이내 유증상자 접촉 여부
4. 동거인 감염 여부
5. 동거인 완치 여부

## AS-IS 서버 전송 방식

기존 프론트는 질문 ID나 질문 코드를 보내지 않고, `answer` 배열의 위치와 숫자 값으로 답변을 전송했다.

```http
POST /v1/selftest/{memberId}
Authorization: Bearer {accessToken}
Content-Type: application/json
```

```json
{
  "currentCondition": [
    "CONDITION_FEVER",
    "CONDITION_COUGH"
  ],
  "vaccineStatus": {
    "temperature": 36.5,
    "isVaccinated": true,
    "vaccinatedDate": "2026-07-15"
  },
  "answer": [
    { "value": 0 },
    { "value": 1 },
    { "value": 0 },
    { "value": 1 },
    { "value": 2 },
    { "value": 0 },
    { "value": 1 }
  ]
}
```

주요 선택값은 다음과 같다.

- 예: `0`
- 아니오: `1`
- 모름: `2`

## TO-BE 서버 전송 형태

두 문항을 삭제하면 답변 배열은 7개에서 5개로 변경된다.

```json
{
  "answer": [
    { "value": 0 },
    { "value": 1 },
    { "value": 1 },
    { "value": 0 },
    { "value": 1 }
  ]
}
```

## 순서 매핑 변경

| TO-BE 순서 | 문항 | AS-IS 순서 |
|---:|---|---:|
| 1 | 증상 시작 시점 | 1 |
| 2 | 급성 호흡기 증상 | 2 |

| 4 | 동거인 감염 여부 | 6 |
| 5 | 동거인 완치 여부 | 7 |

## 서버 및 DB 영향

프론트 화면에서 문항만 삭제하면 충분하지 않다. 서버가 기존 7개 배열 위치를 기준으로 처리하면 3번 이후 답변의 의미가 달라진다.

백엔드에서 확인하거나 수정해야 할 항목:

- 답변 개수 검증을 7개에서 5개로 변경
- 문항 순서와 답변 위치 매핑 변경
- 기존 3번 및 5번 문항 처리 제거
- 기존 4번 문항을 신규 3번으로 매핑
- 기존 6번 문항을 신규 4번으로 매핑
- 기존 7번 문항을 신규 5번으로 매핑
- 기존 4번 답변에 따른 5번 문항 건너뛰기 로직 제거
- 동거인 없음 선택 시 신규 5번을 건너뛰는 로직 유지
- DB 문항 마스터가 있다면 삭제 또는 비활성화
- 관리자 화면의 문항 및 결과 표시 순서 변경
- 기존 진단 이력의 7문항 데이터 보존 및 조회 호환성 검토

## 현재 프론트 상태

현재 `self-web` 로컬 작업본은 다음 상태다.

- 세부 문항 수: 5개
- 삭제 대상 두 문항: 제거 완료
- `answer` 배열: 현재 문항 수를 기준으로 5개 생성
- 동거인 감염 여부에서 `아니오` 선택 시 마지막 완치 문항을 건너뜀
- `FRONTEND_ONLY = true`이므로 실제 서버 전송은 현재 우회 중

## 권장 API 구조

현재처럼 배열 위치만 보내면 문항 추가·삭제 시 서버와 프론트의 의미가 쉽게 어긋난다. 백엔드 연동 시 질문 코드를 함께 보내는 방식이 안전하다.

```json
{
  "answers": [
    {
      "questionCode": "SYMPTOM_STARTED_AT",
      "value": 5
    },
    {
      "questionCode": "ACUTE_RESPIRATORY",
      "value": 0
    },
    {
      "questionCode": "CONTACT_WITHIN_14_DAYS",
      "value": 2
    },
    {
      "questionCode": "HOUSEHOLD_INFECTED",
      "value": 1
    }
  ]
}
```

질문 코드를 사용하면 건너뛴 문항을 억지로 기본값 `0`으로 채우지 않아도 되고, 기존 진단 이력과 신규 진단 이력을 버전별로 구분하기도 쉽다.

## 결론

프론트의 문항 삭제는 이미 반영되었다. 실제 연동 전에는 서버와 DB가 기존 7문항 배열 위치에 의존하는지 확인하고, 5문항 구조에 맞춰 검증·저장·조회·관리자 표시 로직을 함께 변경해야 한다.
